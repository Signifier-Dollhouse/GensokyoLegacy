# Decision log

## Resolved

### D1 — Loader target

**Forge 1.20.1 only.** NeoForge 1.20.1 is a different API from NeoForge 1.21, so
supporting both would double the porting work and force a loader abstraction
over every loader-specific call. The reference repo is Forge 1.20.1.

### D2 — L2 library strategy

**1.20.1 L2 2.x with the legacy API, plus only the contents the mod needs.**
The 1.20.1 libraries exist for every module the mod uses. L2Core did not exist
in 1.20.1 — it was split out of L2Library in 1.21.1 — so `L2Library-1.20` is the
L2Core stand-in.

Consequences:

- The libraries keep their 1.20.1 API and class location (D20–D23). The mod is
  rewritten to that surface.
- Missing library classes are added only when they are genuine library features.
  The registration wrappers (`Reg`, `SR`, `Val`, `AttReg`, `AttVal`, `CdcReg`,
  `CdcVal`, `DCReg`, `DCVal`, `SimpleEntry`, `LegacyHolder`, `EnumCodec`) and the
  data-map helper live in a mod-side compat layer (O6).
- `L2Library` also gains `util/raytrace` and `init/explosion` at their legacy
  paths.
- The L2Core enchantment system is **out of scope**. Exception:
  `DataGenHolder`, which lives in the enchantment package but is a generic
  datagen holder used by `QuestDialogData` and `StructBuilding`.
- Only DanmakuAPI and FastProjectileAPI need a full port.
- L2DamageTracker and L2Tabs are refactored in 1.21.1. They keep the legacy
  1.20.1 API and the mod is adapted to them; the refactor is not backported.
- Data maps are replaced by the `BaseConfig` / `ConfigTypeEntry` system already
  present in l2library 1.20.1.

### D3 — Danmaku and spell cards

**Port both libraries.** 91 mod files and 284 imports depend on them. Cutting
danmaku would remove a core feature; adopting the reference's in-mod
implementation would fork the API. Both ports are standalone repos and can be
done in parallel with the mod.

The 1.20.1 reference is `Youkai-Homecoming-1.20` `main`: FastProjectileAPI is
vendored there (46 files) and the danmaku/spell implementation is in-mod. The
backport lifts that code into the library package layout. The reference is not
expected to be binary-compatible with the backported Gensokyo Legacy; its
`1.20/lite` branch is the pure-food variant.

### D4 — Data components

**Shim layer over NBT.** 27 files use `DataComponents` / `DataComponentType`.
A `compat.components` package mirrors the used API surface over NBT and keeps
call sites intact. The surface is enumerated and frozen in phase A2 so the shim
does not grow.

### D5 — Registration

Use Registrate `MC1.20-1.3.11` and `l2library.base.L2Registrate`. Add the missing
helpers (`loc`, `registerSynced`, `registerUnsynced`, `potion`, `particle`,
`registerClient`) to the backported L2Registrate. `DeferredHolder` becomes
`RegistryObject`. `ProviderType.DATA_MAP` has no 1.20.1 equivalent.

### D6 — Networking

Rewrite the 48 packets onto l2serial 1.2.6 `SerialPacketBase` /
`BasePacketHandler`, which use a Forge `SimpleChannel` and
`NetworkEvent.Context`. Do not port the 3.x `PacketHandler` and
`StreamCodec` networking wholesale; only the pieces the mod calls are backported.

### D7 — Worldgen

`NeoForgeRegistries.Keys.BIOME_MODIFIERS` → `ForgeRegistries.Keys.BIOME_MODIFIERS`;
generated path `data/<modid>/neoforge/biome_modifier` →
`data/<modid>/forge/biome_modifier`. `FlatCheckStructure` follows the reference
`FlatStructure`. TerraBlender 1.20.1-3.0.1.10.

### D8 — Compat

Curios 5.10, JEI 15.20, Patchouli 1.20.1, youkaisfeasts 0.5.2, farmersdelight
family. Drop `twilightdelight`, `lendercataclysm`, `lionfish-api` and
`twilightforest` — no code references. Touhou Little Maid is decision O3.

### D9 — Java 21 → 17

Replace 34 `List.getFirst()`, 3 `getLast()` and 15 `Math.clamp`. No record
patterns or switch patterns were found. Records and sealed types are fine on 17.

### D10 — Mixins, access transformer, events

`compatibilityLevel` `JAVA_21` → `JAVA_17`; audit all 21 mixins and every AT
entry. Event bus moves from `net.neoforged.bus.api` to
`net.minecraftforge.eventbus.api`; `NeoForge.EVENT_BUS` →
`MinecraftForge.EVENT_BUS`; `ClientTickEvent.Post` →
`TickEvent.ClientTickEvent.Phase`; `RegisterGuiLayersEvent` →
`RegisterGuiOverlaysEvent`; `Capabilities.*` → `ForgeCapabilities.*` with
`LazyOptional`.

### D11 — Datapack registries

Port `DatapackReg` / `CdcVal` onto 1.20.1 `DataPackRegistryEvent.NewRegistry`.
l2serial 1.2.6 lacks `CodecAdaptor` and `Handlers.registerReg`; both are in the
D2 backport list.

### D12 — Data maps

No data maps in 1.20.1. Use the `BaseConfig` / `ConfigTypeEntry` system in
`l2library.serial.config`: a `BaseConfig` subclass with `@ConfigCollect` fields,
registered through a `PacketHandlerWithConfig` channel, merged by
`ConfigMerger`, generated by `ConfigDataProvider`. `MenuLayoutConfig` is the
worked example. Compostables move to `ComposterBlock.COMPOSTABLES`; furnace fuel
moves to `IForgeItem#getBurnTime` / `FurnaceFuelBurnTimeEvent`. The l2tabs
icon/order maps disappear because the legacy tab API takes both as arguments to
`TabRegistry.registerTab`.

### D13 — Entities

Backport `SyncedData`. `ItemStack.OPTIONAL_CODEC` becomes NBT.
`EquipmentSlotGroup` is absent; `AttributeModifier` uses UUIDs instead of
`ResourceLocation`.

### D14 — Structures

Audit `MultiSpreadPlacement`, `SetDataProcessor`, `PieceTree`, `GLSinglePiece`,
`ChunkGeneratorStructureState` and the `NoiseBasedChunkGenerator` constructor
against 1.20.1.

### D15 — Client and rendering

GeckoLib 4.x for 1.20.1; audit `GeoEntityRenderer`, `GeoModel`, `GeoBone`,
`GeoLayer`, `GeoItem`. `GuiGraphics` differs. Audit the `ItemInHandRenderer`,
`AbstractContainerScreen` and `LocalPlayer` mixins.

### D16 — Config

`ConfigInit` → `ForgeConfigSpec`. `registerSynced` / `registerUnsynced` are added
to the backported L2Registrate.

### D17 — Assets and data formats

`neoforge.mods.toml` → `mods.toml`; `data/neoforge` → `data/forge`;
`net.neoforged.neoforge.client.model.generators` →
`net.minecraftforge.client.model.generators`; `pack.mcmeta` format 15.

### D18 — Tools and datagen

`src/test/java/organize/*` are `main()` utilities, not JUnit. Update
`tools/*.py` paths and formats. Remove or replace
`testImplementation "com.mojang:datafixerupper:8.0.16"` — it is a 1.21 artifact
and is unused in `src/test`. Regenerate and commit all generated output.

### D19 — L2DamageTracker and L2Tabs

**Legacy 1.20.1 API.** Both were refactored in 1.21.1. The 3.x
`DamageData`/`L2Tabs.GROUP` surfaces are not ported; the mod's call sites move to
`AttackListener`/`AttackCache` and `TabRegistry.registerTab(priority,
factory, icon, title)`. `L2Tabs` is rebuilt from the `entity` branch, which is
the legacy 1.20.1 code (`main` is the experimental tab rework adopted in
1.21.1). `L2DamageTracker` is rebuilt from `main`. The published 0.3.7 / 0.3.3
jars are stale.

### D20 — L2Serial

**Legacy 1.20.1 API; backport fixes only.** Keep `BasePacketHandler`,
`SimpleChannel`, `SimplePacketBase` and `SerialPacketBase` as abstract classes.
Do not introduce the 3.x `PacketHandler`/`IPayloadContext`/`StreamCodec` model.
The mod's 44 packets become classes extending `SerialPacketBase` with
`handle(NetworkEvent.Context)`; `GLPackets` becomes a `PacketHandlerWithConfig`
so `ConfigTypeEntry` can use the same channel.

### D21 — L2Library / L2Core

**Legacy 1.20.1 API and class location.** Backport the missing classes into
`dev.xkmc.l2library.*`, reusing the legacy package where one exists:

| `capability.attachment.GeneralCapabilityTemplate` | `capability.entity.GeneralCapabilityTemplate` |
| `capability.player.*` | `capability.player.*` (legacy lifecycle) |

The 3.x `L2Registrate` helpers and the `SimpleEntry` / `LegacyHolder` / `Val`
wrappers stay in the mod-side compat layer (O6); the library jar keeps its
legacy base unchanged.

### D22 — L2ItemSelector

**Legacy 1.20.1 API.** `IItemSelector` keeps `getIndex(Player)`, `getList()`,
`move(int, Player)` and `swap(Player, int)`; `getSelection(Player)` returns the
selector, not a holder. The six mod listeners drop their `ItemStack` parameters.
The 3.x `overlay/` package is not added: the same classes already exist in
`l2library.base.overlay`.

### D23 — L2ModularBlock

**Backport the 3.x contents at the legacy class location.** Add
`BlockTemplates`, `VoxelBuilder`, the waterlogged delegate variants, the new
`mult` interfaces (`UseItemOnBlockMethod`, `UseWithoutItemBlockMethod`,
`PathFindBlockMethod`, `PlayerDestoryBlockMethod`, …) and `DoubleBlockImpl` at
the package root. Do not move the six delegate classes into `core/`; the mod's
`l2modularblock.core.*` imports move to the root package.

### D24 — L2 dependency policy

**L2Library is an explicit external dependency, not jar-in-jar'd.** The mod
compiles and runs against `l2library-2.5.6-slim`; the jars the full L2Library
ships (Registrate, mixinextras-forge, l2serial, l2tabs, l2screentracker,
l2modularblock, l2itemselector) are declared `implementation` too, so the dev
classpath has them without nesting them in the mod jar. Only libraries the
full L2Library does not carry are `jarJar`'d: l2damagetracker,
FastProjectileAPI, DanmakuAPI, GeckoLib and TerraBlender.

## Open

### O1 — Package for the backported L2Core classes (resolved)

**Option B: backport into `dev.xkmc.l2library.*` and rewrite the imports.**
Resolved by D21. The mapping is in D21; the only classes without a legacy home
are the `init.reg.*` framework, which keeps its 3.x subpath under the legacy
root (O6).

### O2 — `l2modularblock.impl.DoubleBlockImpl` (resolved)

**Restore the 1.21.1 content first, then port it down.** The 1.21.1 branch
(`origin/1.20.4`) is missing exactly `impl/DoubleBlockImpl`,
`mult/PathFindBlockMethod` and `mult/PlayerDestoryBlockMethod` — the three
classes the mod uses. Restore them on the 1.21.1 branch from the working copy,
then port the whole 1.21.1 set to the `1.20` branch at the legacy root (D23).
Do not reimplement them independently.

### O3 — Touhou Little Maid (resolved)

**Keep.** The compat package is small and Youkai-Homecoming-1.20 carries the
same integration, so it is a direct port. Guard every reference with
`ModList.get().isLoaded(...)` as before.

### O4 — `l2harvester` (resolved)

Not ported and never imported by GensokyoLegacy. It is still needed at
runtime: `youkaisfeasts` declares it mandatory and the slim build does not
ship it. Use the 1.20.1 build from `Youkai-Homecoming-1.20`
(`libs/l2harvester-0.1.2.jar`) and jar-in-jar it; its two mixin variants stay
nested inside that jar.

### O5 — L2ScreenTracker (resolved)

**Use the legacy names.** Keep `dev.xkmc.l2screentracker` and `L2ScreenTracker`.
Backport `CacheMouseToClient` and `MouseCache` from the 3.x branch into the
legacy library; the four mod call sites then use
`L2ScreenTracker.PACKET_HANDLER.toClientPlayer(new CacheMouseToClient(), sp)`.
The other 18 imports are a package rename only.

### O6 — Registration framework (resolved)

**Compat layer inside GensokyoLegacy, on need.** Most of the 3.x registration
wrappers are not needed. Put only what the mod actually uses in a mod-side
package (e.g. `compat/l2reg`); do not add `Reg`, `SR`, `Val`, `AttReg`, `AttVal`,
`CdcReg`, `CdcVal`, `DCReg`, `DCVal`, `EnumCodec`, `SimpleEntry` or
`LegacyHolder` to the L2Library jar. `DataMapReg` disappears with D12.

The L2Library jar therefore only needs the genuine library classes
(`SyncedData`, `BaseSavedData`, `serial/loot`, `SchedulerHandler`, `ConfigInit`)
if they are not also put in the compat layer. Default: keep them in the compat
layer too, so the library jar stays a plain rebuild.

### O7 — BaseConfig read semantics (confirmed)

Confirmed: the ten `DataMapReg` fields become `ConfigTypeEntry` instances, the
data types become `@SerialClass` `BaseConfig` subclasses, reads become
`entry.getEntry(key.location())`, datagen uses `ConfigDataProvider`, and the
mod's handler becomes a `PacketHandlerWithConfig`. This is the A4 phase's
definition of done.
